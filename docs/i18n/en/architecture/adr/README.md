# Architecture Decision Records

ADRs capture significant decisions whose context and trade-offs should survive beyond the implementation that introduced them.

## Required sections

- **Status** — proposed, accepted, superseded, or rejected.
- **Context** — the problem and constraints.
- **Decision** — the chosen approach.
- **Alternatives** — meaningful options considered.
- **Consequences** — benefits, costs, risks, and follow-on work.

## Naming

Use sequential files such as `0001-organization-tenant-boundary.md`.

No proposal from the source archive is automatically an accepted ADR. Candidate decisions should be promoted only after validation against the current Brk-Trkr repositories.
