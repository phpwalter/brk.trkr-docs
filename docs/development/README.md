# Development Documentation

This section explains **how engineers work on Brk-Trkr**.

Authoritative development documentation should live here when its primary purpose is to help contributors set up, understand, build, test, debug, review, and change the system safely.

## Planned structure

- `getting-started.md` — local prerequisites and setup.
- `repository-structure.md` — responsibilities and relationships of the Brk-Trkr repositories.
- `workflow.md` — branch, commit, pull-request, review, and release workflow.
- `standards/` — coding, documentation, API, database, and frontend standards.
- `testing/` — testing strategy, fixtures, coverage expectations, and test execution.
- `debugging/` — recurring diagnostic procedures and troubleshooting guidance.
- `tooling/` — local tools, scripts, generators, linters, and automation.

## Content rules

- Prefer durable engineering guidance over one-time implementation summaries.
- Convert useful historical debugging or implementation notes into reusable procedures before placing them here.
- Keep product behavior in Product and system design in Architecture.
- Link to source repositories where code or configuration is the actual source of truth.
